##  Gemini AI Quiz Agent
StudyHive incorporates an AI agent powered by the **Google Gemini API** (`gemini-1.5-flash`, `gemini-2.0-flash`, `gemini-1.5-pro`):
- **On-Demand Interactive Quizzes**: Automatically generates multi-choice questions with 4 plausible options, timer countdown, and answer keys.
- **Generate from Study Notes**: Pass any uploaded summary, cheat-sheet, or lecture note to generate targeted exam questions.
- **Immediate Concept Explanations**: Illuminating explanations generated by Gemini for every option to reinforce peer learning.
- **Room-Wide Synchronized Quiz Sessions**: Any host or student can launch a quiz; scores synchronize in real-time onto a live room leaderboard.
- **Resilient Fallback Mode**: If no key is entered yet or offline, includes built-in curated CS question banks so testing is always instant.

## 🛠️ Tech Stack & Architecture

- **Frontend**: React 19, Lucide Icons, Canvas-Confetti, Web Audio API Sound Synthesizer (Zero-dependency chimes & focus noise).
- **Backend**: Node.js, Express, Socket.io (Event-driven room sockets and server authoritative countdown ticks).
- **AI Engine**: Google Gemini REST API (`@google/generative-ai` compatible).
- **Persistence & State**: In-memory synchronized room & message store with easy extensibility to MongoDB & Cloudinary.

### Firebase accounts, interests, and room access
StudyHive requires a Firebase project for sign-in and profile storage.

1. Create a Firebase project and register a Web app. In Authentication, enable **Email/Password**. Create a Firestore database.
2. Copy the Web app settings into the matching `REACT_APP_FIREBASE_*` entries in your local `.env` (use `.env.example` as the template).
3. Create a Firebase service account for the server. Keep its JSON file outside this repository, then set `FIREBASE_PROJECT_ID` and `GOOGLE_APPLICATION_CREDENTIALS` in `.env` to the project ID and full file path. Never paste the service account JSON into chat or commit it.
4. Restart `npm run dev`. New accounts choose a display name and subjects; those interests rank public rooms. Public rooms can be joined by any signed-in member. Private rooms require the complete invite URL. Only the creator can delete a room.

Profiles and interests are stored in Firestore. Room content currently uses the app’s in-memory store and is cleared when the server restarts.

### 3. Running the Application
Start both the backend server and frontend development server with one command:
```bash
npm run dev
```
- **Frontend App**: `http://localhost:3000`
- **Backend API & WebSockets**: `http://localhost:5000`
